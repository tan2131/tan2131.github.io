# 新版板卡 LCD 上电白屏问题复盘与排查流程

> 用途：记录一次新旧板卡 LCD 首次上电白屏问题的真实排查过程，并沉淀为下一次可以直接执行的流程。本文区分**实测现象、当前推断和仍待验证的结论**，避免把相关性写成确定因果。

## 一、问题背景与现象

新版与旧版的主要改动是 PCB 布局，以及屏幕连接方式由焊接改为可插拔。新版出现上电后 LCD 白屏；在跳过约 30 秒预热倒计时后，手动拔插屏幕又能显示倒计时或后续数据。屏幕重新插上后可正常显示，说明问题与启动阶段的初始化、复位、上电时序或连接状态有关，但仅凭这一现象还不能锁定原因。

## 二、排查过程复盘

### 1. 对比旧版与新版的显示通信波形

- **操作：** 测量底板到屏幕的 CLK、DIO、STB 等通信信号，并比较新旧板波形。
- **观察：** 当时未从波形对比中找到能直接解释白屏的差异。
- **评价：** 这是合理的起点。后续应进一步比较首条初始化命令的时间、时钟频率、脉宽、边沿、逻辑电平、数据建立/保持时间，以及复位释放到首条命令之间的间隔。只看“有没有波形”不够。

### 2. 用拔插现象判断故障发生阶段

- **操作：** 观察上电后 30 秒预热倒计时；跳过倒计时后拔插屏幕。
- **观察：** 拔插后屏幕可以显示。
- **推断：** LCD 重新上电/复位后能够工作，因此启动时的复位状态或初始化过程值得优先排查。
- **边界：** 这不能直接证明一定“没有复位指令”，也不能单独证明是电压问题。拔插会同时改变屏幕供电、复位芯片状态、连接接触和重新发送命令的时机。

### 3. 检查电源与复位时序

- **操作：** 测量供电电压、上电浪涌，并观察复位相关信号；将屏幕互换测试。
- **观察：** 电压测量和上电浪涌对比没有发现明显异常。复位相关信号测到约 250 ms 的时间差异；互换屏幕后，较慢现象跟随板子而非屏幕。
- **评价：** 这缩小了范围，说明问题更可能在板侧，而不是单块屏幕本身。但“时间差约 250 ms”必须明确测量的是哪个信号、以哪个阈值作为起止点、在哪两个测试点测得，以及差异是脉宽、延迟还是相位差。没有这些条件，不宜直接认定它就是故障原因。

### 4. 尝试软件延时与初始化补救

- **操作：** 增加初始化等待时间、调整 SPI 位操作延时，并增加倒计时期间对 LCD 恢复标志的处理。
- **观察：** 修改后，重新拔插屏幕可以恢复显示，倒计时也能正常显示；但首次冷启动仍然白屏。
- **评价：** 这属于改善恢复能力，并未解决首次启动失败。延时只能在“时序余量不足”这一类原因成立时起作用；若是器件差异、引脚电气行为、错误的复位连接或命令/时钟不兼容，盲目加长延时未必有效。
- **代码方面的教训：** 将 SCK、DC、SDA 等通信脚拉低再拉高，并不等于对 LCD 的 RES 引脚执行了硬件复位。硬件复位应以原理图和屏幕控制器数据手册为准，不能把普通通信线的电平变化当作复位替代方案。

### 5. 进一步检查 MAX809T 复位芯片

MAX809 系列是电源监控/复位芯片：当被监测电源低于阈值时使 RESET 有效；电源恢复越过阈值后，RESET 仍会保持有效一段规定时间，再释放。具体复位脉宽取决于准确型号、封装及数据手册参数，并不是任何 MAX809T 都应被当作固定 250 ms。

检查时必须先确认：

1. MAX809T 的 VCC、GND、RESET 实际接到哪里；RESET 是接 MCU、LCD 的 RES，还是其他节点？
2. 示波器测到的是 MAX809T 输出脚，还是 LCD/MCU 引脚处的实际复位电平？
3. RESET 的低电平宽度、释放阈值和电源爬升是否符合相应器件的要求？
4. 电源达到阈值之后，复位释放到首条显示命令之间有多少时间？

参考：Analog Devices 的 MAX809T 产品/数据手册资料：<https://www.analog.com/en/products/max809t.html>。

### 6. 互换主控芯片，故障随芯片转移

- **操作：** 将新旧板的主控芯片互换。
- **观察：** 原本异常的新板恢复正常；原本正常的旧板转而出现类似白屏问题。
- **结论强度：** 这是本次最有价值的定位结果，强烈指向主控芯片本身，或与该芯片一起转移的因素（例如芯片版本/批次、电气特性、引脚行为、焊接状态）。
- **尚未证明：** 仅凭封装外观少了一个圆形标记、丝印相同或故障随芯片移动，还不能断言它一定是假货，也没有证明约 250 ms 的差异就是唯一根因。最好在条件允许时做一次反向复测/恢复原状复测，并用同型号、来源可靠的芯片作对照。

## 三、复盘结论：哪些确定，哪些仍是假设

### 已观察到的事实

- 新版首次上电时出现白屏。
- 屏幕重新拔插后能够显示。
- 供电电压和上电浪涌的已有测量没有发现明显异常。
- 某个复位相关时序存在约 250 ms 的差异，但需补全测点和定义。
- 主控芯片互换后，异常现象跟随主控芯片转移。

### 当前最合理的判断

主控芯片或与其绑定的器件/装配因素是首要调查对象；软件延时和热插拔恢复逻辑只能改善启动失败后的恢复体验，不能作为根因已经消除的证据。

### 暂时不能下的结论

- 不能仅凭外观判定芯片为盗版/假货。
- 不能仅凭 250 ms 的测量差异认定复位脉宽就是唯一原因。
- 不能把“屏幕拔插后恢复”直接等同于“LCD 控制器本身坏了”或“复位芯片坏了”。

## 四、下次遇到同类问题的排查流程

### 第 0 步：先定义可复现的故障

记录：使用哪块板、哪块屏幕、哪根线、供电电压、固件版本；“白屏”是背光亮但没有内容、全白、全黑、乱码，还是只显示部分内容；冷启动失败率是多少；屏幕拔插后多久恢复。先固定测试条件，不要同时换屏、换线、换固件和改代码。

### 第 1 步：建立新旧板 A/B 对照

在相同电源、相同屏幕/排线、相同固件和相同测量方式下，对比正常板与异常板。优先对比：LCD 供电、主控供电、复位信号、通信时钟/数据/片选或 STB，以及上电后第一条初始化命令的时间。一次只改变一个变量。

### 第 2 步：先测电源，再测复位

用示波器直接在器件供电脚附近测量，不要只看电源入口或万用表读数。比较电源爬升、跌落、纹波和上电时序。

随后同时观察电源与复位信号：标注测点、参考地、阈值、低电平宽度、释放时刻。分别在复位芯片输出端和目标器件的 RES/RESET 引脚处测量，以确认信号真正到达了芯片。

### 第 3 步：验证复位释放后的第一组通信命令

示波器触发在复位释放边沿，检查第一条命令是否出现、时间是否足够、逻辑电平是否正确、时钟极性/相位和数据顺序是否符合控制器要求、STB/CS/DC 状态是否正确。新旧板尽量用相同时间尺度叠加比较。若没有示波器多通道条件，分次测量也要保持触发点和时基一致。

### 第 4 步：单变量替换，定位“故障跟谁走”

按风险和难度从低到高替换：屏幕 → 排线/连接器 → 供电/复位器件（需按原理图确认）→ 主控芯片。每次替换前后都记录结果，完全断电后再操作，并注意器件方向、静电、焊盘和焊接质量。

关键验证方式是 A/B 互换：

- 正常板 + 可疑器件，是否故障？
- 异常板 + 正常器件，是否恢复？
- 若条件允许，将器件换回，现象是否再次反转？

故障随器件移动是强证据，但反向复测可排除焊接、焊盘损伤或操作带来的混杂因素。

### 第 5 步：最后再改软件

先保存原固件和波形；随后一次只改一个项目，例如初始化命令顺序、复位后等待时间或 SPI 时序。每个改动都写明假设、预期现象和实际结果。若只在热拔插后成功，应记录为“恢复路径有效”，不能记录为“冷启动根因已修复”。

### 第 6 步：判断是否为假货或批次/版本问题

- 拍摄芯片顶标、底部/封装、批次标记和 PCB 焊接状态。
- 追溯采购渠道、料号全称、批次和供应商；核对厂商订货型号、封装与丝印规范。
- 使用来源可靠的同型号器件在同板、同固件、同供电条件下对照。
- 对照关键电气行为：启动/复位时序、GPIO 上电状态、时钟配置、通信波形、启动电流等。
- 需要做供应商质量判断时，保存样品、波形和互换测试记录，向供应商或原厂渠道申请分析。

外观标记差异只能作为线索，不能单独作为假货结论。

## 五、现场排查记录表

每轮测试建议记录以下信息：

| 项目 | 记录内容 |
|---|---|
| 板卡/版本 | 旧版或新版、PCB 版本、序列号 |
| 屏幕/排线 | 型号、编号、连接方式 |
| 固件 | 版本号、编译时间、关键修改 |
| 供电 | 输入电压、器件脚处电压、波形截图编号 |
| 复位 | 测点、阈值、低电平宽度、释放时间 |
| 通信 | CLK/DIO/STB 或 SCK/SDA/DC/CS 波形截图编号 |
| 操作变量 | 本轮只更换/修改了什么 |
| 结果 | 冷启动、热拔插、重复测试结果 |
| 结论等级 | 已确认 / 高度怀疑 / 待验证 |

## 六、可复用的排查原则

1. **先复现，再测量；先对照，再猜原因。**
2. **电压正常不代表时序正常；有波形不代表协议正确。**
3. **复位信号要测到目标芯片引脚，而不只是复位芯片输出。**
4. **热拔插恢复说明重新上电/复位/初始化路径能工作，不等于首次启动根因已找到。**
5. **一次只改变一个变量，记录预期和实测。**
6. **故障随器件移动是重要证据，但假货判断需要来源与器件验证。**
7. **最终修复必须用多次冷启动、快速重启、屏幕拔插及正常显示等测试验证。**

## 七、本次问题的后续验证建议

1. 用同一套示波器设置同时记录正常板和异常板的 MCU 供电、LCD 供电、MAX809T RESET、LCD RES（若接出）以及首条通信命令。
2. 记清约 250 ms 差异究竟发生在哪两个边沿之间，并将该时间与复位脉宽、供电越阈值时间、首条初始化命令时间分别对应起来。
3. 在焊接条件允许且不损坏板子的前提下，再做一次反向互换或换入来源可靠的同型号主控芯片验证。
4. 确认后再处理供应商/批次问题；不要继续靠增加延时掩盖异常器件行为。
